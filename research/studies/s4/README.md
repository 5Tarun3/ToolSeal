# Study 4 — Translation fidelity at scale (RQ4)

**Status: run, Windows only.** Every number below is in [`RESULTS.md`](RESULTS.md)
and [`results.json`](results.json), generated by `uv run python -m bench s4`
after `uv sync --group research`. The method is probe P0's, registered in
[`../../evaluation-protocol.md`](../../evaluation-protocol.md#study-4--translation-fidelity-at-scale-rq4);
departures are in its deviations table.

## What was measured

Seven units: an adapter at one version, in one configuration. All of them load
the same fixture server, [`bench/s4_fixture_server.py`](../../../bench/s4_fixture_server.py).
It has P0's three tools unchanged, plus nested-object, array, optional and
error-path tools, which P0 had no fixture for.

| unit | route |
| --- | --- |
| `langchain-mcp-adapters` 0.3.2 | MCP → LangChain |
| `crewai-tools` 1.15.14 | MCP → CrewAI |
| `openai-agents` 0.20.0 | MCP → OpenAI function tool |
| `openai-agents` 0.20.0, strict schemas | the same, `convert_schemas_to_strict=True` |
| `langchain-core` 1.5.4 `convert_to_openai_tool` | MCP → LangChain → OpenAI function schema |
| `agent-framework-core` 1.21.0 | MCP → Microsoft Agent Framework |
| `agent-framework-core` 1.21.0, FIDES labels | the same, `apply_mcp_security_labels` (experimental) |

Each unit was scored three ways:

- **What it declares**, against the fixture's own `tools/list`.
- **What it does with an invalid call.** A call log written by the server
  before it validates shows whether the call left the client.
- **Restoration.** Where the lattice models the target, toolseal's generated
  binding was run with its real guards against the real translated tool.

## Findings

**1. P0 holds at scale for annotations.** `langchain-mcp-adapters` carries all
four hints and the title. Every other adapter drops the four hints. `openai-agents`
keeps only the title, on a private attribute. Microsoft's FIDES path converts the
hints into restriction-only integrity and confidentiality labels instead of
carrying them, so they are scored `mutated`. No adapter except LangChain's lets a
consumer tell `destructiveHint: true` from a read-only tool. Two adapters expose
an approval switch: `openai-agents`' `needs_approval` and agent-framework's
`approval_mode`. Neither is set from the hint.

**2. Client-side enforcement is the exception, and it is partial.** Ten invalid
calls were made through each adapter:

- `langchain-mcp-adapters` and `openai-agents` (both modes) sent all ten to the
  server.
- `agent-framework` stopped one, the top-level `enum`.
- `crewai-tools` stopped seven. P0 never tested this: it rebuilds the schema as
  a Pydantic model and validates against it. The rebuild loses array
  `minItems`, `maxItems` and `uniqueItems`, and a nullable field's `maxLength`,
  so exactly those three invalid calls still reach the server.

**3. The lattice is wrong about two targets.** It says CrewAI expresses input
constraints, which P0 measured on top-level fields only. Nested and array
constraints are lost.

Strict-mode `openai-agents` changes the meaning of a call: it makes fields the
author left optional required. On the nested tool it fails to convert and falls
back to non-strict without saying so. The lattice entry for `openai_fc` is
`specified`, not `measured`, and both disagreements are what it predicts
wrongly.

**4. The validation guard is never generated.** `lower()` emits
`validate_against_schema` only for a tool that declares `clientValidation`. An
MCP tool never declares it, because MCP cannot express it. So for every MCP
tool lowered into every target, check family G2's compensating guard is absent:
0 of 5 tools in each unit with violations.

**5. Applied by hand, the guard stops only top-level violations.** It does not
descend into `$ref`, `anyOf` or array `items`, so it misses every nested,
array and nullable case in the fixture: 4 of 10 stopped for LangChain and
`openai-agents`.

CrewAI's 7 of 10 is CrewAI's own validation, not the guard's. The guard's
docstring says it is "deliberately small". This is what that costs once
schemas are nested.

**6. Every other generated guard fires when it is generated.**

- Approval stops the destructive call without a terminal.
- The error-channel guard turns flattened `isError` text into an exception.
- The description guard keeps the author's text where CrewAI rewrites it.
- The sidecar guard records the hints in the manifest.

That holds for every unit the lattice models.

**7. `uniqueItems` is unenforced by everything, the fixture server included.**
It is declared through `json_schema_extra` and the server does not check it.
This was found on the first run and kept, not fixed. It is P0's warning made
concrete: a constraint the server does not validate has no second line.

## What this means for C5

C5's mechanism is to lower with compensating guards. The measurement supports
it for every guard except the one that matters most for input safety.

The validation guard is unreachable from MCP. Even when applied by hand it
covers only flat schemas. Two lattice entries need correcting from measurement:

- CrewAI's input constraints.
- `openai_fc`'s required sets, under strict mode.

Microsoft Agent Framework needs a profile of its own. Until it has one, toolseal
cannot lower into it.

These are product changes. They are recorded here and **not** made in the same
change as the measurement, so the numbers above describe the code that was
measured.

## Limitations

- **One platform.** Windows only, with one version of each adapter. A different
  version is a different unit.
- **Carriers are searched by name.** Every `dropped` annotation verdict for an
  adapter P0 did not test was checked against that adapter's source; each
  unit's note in `RESULTS.md` says where. `agent-framework` passes annotations
  only to an optional load callback, which only its FIDES path uses, and that
  path is a unit of its own.
- **Restoration stubs the `@tool` decorator**, as the project's executable-guard
  tests do. The generated binding always imports `langchain_core`'s `@tool`,
  whatever the target, which is itself a defect: a CrewAI binding should not
  need LangChain installed.
- **The OpenAI function-schema route has no runtime.** It is a format, so it has
  declaration verdicts only.
